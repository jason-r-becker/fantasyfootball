# Data preparation

Most draft-room operators should receive prepared private files rather than
regenerate rankings. This page separates the minimum transfer from the
maintainer workflow.

## Input and output map

The draft room requires:

```text
data/YEAR/LEAGUE/config.json
data/YEAR/LEAGUE/clean.csv
```

These inputs are optional but recommended:

```text
data/YEAR/LEAGUE/adp.csv
data/YEAR/source_player_map.json
```

`adp.csv` supplies a consensus `AVG` only when the corresponding `ADP` value in
`clean.csv` is blank. Existing platform ADP always wins. Column-name matching
for `Player` and `AVG` is case-insensitive.

`source_player_map.json` maps source names to canonical `clean.csv` names for
the whole season. The draft room uses confirmed aliases to reconcile platform
picks without fuzzy guessing.

What the repository can create:

| Artifact | Generated by the repository? | Prerequisites |
| --- | --- | --- |
| League directory | No | Create it with `mkdir -p data/YEAR/LEAGUE`. |
| `config.json` | Partly | If missing, `clean_data.py` prompts for team and starter counts and assumes Sleeper. Complete draft-room fields manually. |
| `raw.csv` | Yes | R, `ffanalytics`, `jsonlite`, and `data/YEAR/scoring_profiles.json`. |
| `adp.csv` | No | Obtain a FantasyPros-compatible export separately. |
| `clean.csv` | Yes | `raw.csv`, `adp.csv`, and `config.json`. |
| `source_player_map.json` | Partly | Optional; the weekly lineup workflow can build mappings interactively. The draft cleaner only reads existing mappings. |
| Working CSVs and session JSON | Yes | Starting the draft room creates them and each draft action updates them. |

None of these generation paths reads `.env` or logs in to Sleeper. The R script
retrieves projection sources through `ffanalytics`; the repository does not
automate the FantasyPros ADP download.

## `clean.csv` contract

Treat the supplied file as generated data and do not rename or restructure its
columns during a draft. A complete file produced by `clean_data.py` contains:

```text
Player, Team, Position, Bye, VOR_Floor, VOR_Points, VOR_Ceiling,
Floor, Points, Ceiling, FLEX_VOR_Floor, FLEX_VOR_Points,
FLEX_VOR_Ceiling, Std Dev, ADP
```

The first unnamed CSV column is the saved row index. Player names must be
unique enough to identify a pick. Draft-room positions are `QB`, `RB`, `WR`,
and `TE`; K and DST are tracked separately as unranked selections.

## Prepare season rankings

The legacy interactive cleaner expects these private inputs in the league
directory:

- `raw.csv` — season projections from Fantasy Football Analytics-compatible
  output.
- `adp.csv` — FantasyPros export with `player`, `pos`, `bye`, `avg`, and a
  column named for the configured site, such as `sleeper`.
- `config.json` — at least `teams`, `positions`, and `site`, plus draft-room
  settings described in [Configuration reference](configuration.md). Start
  from the matching platform example in `examples/`.

From the repository root, run:

```bash
uv run python -m fantasyfootball.clean_data
```

Enter the year and league directory name when prompted. The cleaner calculates
value over replacement, joins projections to ADP, prompts for unresolved player
name matches, and writes both `clean.csv` and an initial `live_draft.csv`.
Review every fuzzy match; stop and correct source data rather than accepting an
incorrect identity.

The tracked R script can generate `raw.csv` for every league described in the
private `data/YEAR/scoring_profiles.json`:

```bash
Rscript scripts/generate_ffanalytics_projections.R --year=YEAR
```

It requires R plus the `ffanalytics` and `jsonlite` packages, stores a private
season cache at `data/YEAR/ffanalytics_scrape.rds`, and overwrites each listed
league's `raw.csv`. Use `--refresh` only when a fresh source scrape is intended.
Do not run this command merely to test installation against valuable local
data.

## Before transferring rankings

1. Check `config.json` against the platform's current team count, starting
   positions, round count, and draft type.
2. Open `clean.csv`; confirm it is non-empty and has the complete column set.
3. Check for blank/duplicate player names and unexpected positions.
4. Launch practice mode and confirm the displayed player and ADP-fallback
   counts.
5. Stop the server before copying files, and exclude every generated session
   and working CSV unless an intentional resume is being transferred.
6. Transfer the four input files to the draft-room computer.

## Weekly projection files

In-season lineup analysis uses this current destination pattern:

```text
data/YEAR/LEAGUE/weekly_projections/projections_YEAR_wkWEEK*.csv
```

For a selected year and week, the downloaded base name is
`projections_YEAR_wkWEEK.csv`. The tool moves it from `Downloads` to a
weekday-stamped name such as `projections_YEAR_wkWEEK_d1.csv`; among those
stamped files, the lexically latest match is used. The older per-week directory
layout is obsolete.

Run the lineup tool with explicit values:

```bash
uv run python -m fantasyfootball.set_lineup \
  --year YEAR \
  --week WEEK \
  --league LEAGUE
```

The tool first looks in the current user's `Downloads` directory for the base
projection filename and, if found, moves it into `weekly_projections/` with a
weekday suffix.
